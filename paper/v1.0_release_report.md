# AQX v1.0 Research Release Report

## Research question
Can a risk-aware selector choose among existing quantitative-Python execution backends with low regret while avoiding catastrophic backend-selection errors?

## System
AQX evaluates four execution backends: pure Python, NumPy, Numba, and Numba-parallel. The research selector uses workload features and a risk-aware objective. Earlier versions explored online calibration and abstention; v1.0 freezes the resulting baseline rather than introducing another unvalidated algorithmic change.

## Evidence available at v1.0
The strongest existing benchmark corpus contains 20 measured cases across four workload families and five sizes, with steady-state medians after warm-up. Under the primary rank-holdout protocol, the best lightweight selector achieved 95.0% oracle-hit accuracy and 3.52% mean regret over 60 model predictions. A leave-one-workload-family-out experiment achieved 80.0% accuracy and 12.48% mean regret.

These results are promising but should not be interpreted as proof of general superiority. The corpus is small and the main measurements were collected on one environment. Model predictions are repeated across seeds for robustness analysis, but these repetitions do not constitute independent hardware/workload samples.

## Strongest negative evidence
The v0.3–v0.5 calibration experiments demonstrated that simple pilot extrapolation can be unreliable. The v0.7 study also showed that a generic classifier can make large-regret mistakes. These failures motivated the risk-aware objective in v0.8 and the expanded validation in v0.9.

## Reproducibility
Run `pytest -q` for the correctness suite. Run `python experiments/run_v09_clean.py` to reproduce the lightweight v0.9 analysis using the measured-case artifacts included in the repository. Run `aqx-demo --workload monte_carlo --size 4096` for a fresh local steady-state backend comparison.

## Publication status
AQX v1.0 is a **research release candidate**, not a publication-ready final result. Before submitting a paper, the following should be completed: multi-machine measurements, a larger independent benchmark corpus, stronger automated-tuning baselines, end-to-end decision overhead, and pre-registered or otherwise fixed evaluation splits for the final analysis.

## Appropriate claim
The evidence supports the narrower claim that **risk-aware backend selection is a viable research direction for heterogeneous quantitative Python workloads and can substantially reduce average regret relative to weak selection strategies on the current benchmark corpus**. It does not yet support a claim of universal or production-grade performance superiority.
